# Система управления состоянием диалога

## Обзор

Система управления состоянием диалога позволяет отслеживать текущее "состояние" диалога для каждого пользователя и обрабатывать сообщения в зависимости от этого состояния. Это позволяет реализовать многошаговые диалоги, в которых бот задает последовательные вопросы и обрабатывает ответы пользователя.

## Структура базы данных

Состояние диалога хранится в таблице `dialog_state`:

```sql
CREATE TABLE IF NOT EXISTS dialog_state (
    id SERIAL PRIMARY KEY,
    user_id TEXT NOT NULL,
    status TEXT NOT NULL,
    context JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE(user_id)
);
```

Где:
- `user_id` - идентификатор пользователя
- `status` - текущее состояние диалога (например, `waiting_for_card_name`)
- `context` - JSON-объект с контекстом диалога (например, собранные данные для визитки)
- `created_at` - время создания записи
- `updated_at` - время последнего обновления записи

## Алгоритм обработки сообщений

1. Получаем сообщение пользователя и его идентификатор.
2. Сохраняем сообщение пользователя в историю чата.
3. Проверяем, есть ли у пользователя активное состояние диалога.
4. Если есть активное состояние:
   - Обрабатываем сообщение в соответствии с текущим состоянием.
   - Обновляем состояние диалога или удаляем его, если диалог завершен.
   - Отправляем ответ пользователю.
5. Если нет активного состояния:
   - Проверяем, содержит ли сообщение триггер-слова.
   - Если содержит, инициализируем новый диалог.
   - Если нет, обрабатываем сообщение как обычный запрос.

## Примеры состояний диалога

### Создание визитки

1. `waiting_for_card_name` - ожидание имени для визитки
2. `waiting_for_card_title` - ожидание должности
3. `waiting_for_card_company` - ожидание названия компании
4. `waiting_for_card_contacts` - ожидание контактной информации

## Расширение функциональности

Для добавления новых типов диалогов:

1. Добавьте новые состояния в функцию `handleDialogState`.
2. Добавьте инициализацию новых диалогов в функцию `initializeDialogState`.
3. При необходимости добавьте новые триггер-слова в объект `triggerRouter`.
